   Regra violada: architecture.md §4 — "*Regra absoluta:* componente jamais fala com o servidor. Todo acesso à API passa por uma camada de serviço/repositório". O `AuthService` faz `inject(HttpClient)` (`apps/web/src/app/features/auth/auth.service.ts:34`) e `HttpClient` só existe na árvore de DI quando `provideHttpClient()` é registrado — hoje não é (`grep provideHttpClient` em `apps/web`: **0 ocorrências**).
   Prejuízo concreto: no primeiro boot, `''` redireciona para `login` → o lazy chunk carrega → o `LoginComponent` é instanciado → `inject(AuthService)` → `inject(HttpClient)` → `NullInjectorError: No provider for HttpClient!` (NG0201). O router engole o erro de navegação e **a tela de login nunca renderiza** — o entregável de CA2/CA3 não existe no app. Nenhum teste pega isso: o spec do `LoginComponent` mocka o `AuthService` (`login.component.spec.ts:39`) e o `app.spec.ts` não navega para rota nenhuma.
   Nota de escopo: o arquivo a corrigir (`app.config.ts`) não foi tocado por este diff; aponto porque **é este diff que torna o caminho alcançável** (antes, `routes = []` e nada era instanciado). Correção de uma linha — pode ir em commit de manutenção se o arquiteto preferir.
